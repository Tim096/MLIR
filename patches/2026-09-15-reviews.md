- arith 已經給旗標實質語意：`ArithOps.cpp` 的 fold 用 `nsz`（L1299、L1325、L1574）、`nnan`（L1393、L1574）、`contract`（L1835）、`ninf`（L3341）；`AttrToLLVMConverter.cpp` L16–23 七個旗標 1:1 對到 LLVM。
- arith 自己對 `nsw`／`nuw` 的寫法就是 self-contained（`ArithOps.td` L285–288「the result is poison」），dialect description L25–28 已定義 poison 傳播。照這套字彙寫 fastmath 就能滿足 kuhar。
- `math` dialect 8 個 op 共用 `Arith_FastMathAttr`（`MathOps.td`），所以 `afn` 在 arith 裡有實際對象。
- precedent：`IRDL VariadicityAttr`、`ArmSME TypeSizeAttr` 都在 `EnumAttr` 上寫 description。

**要貼的 review（Comment）**：內容是回應 kuhar 的要求，給一份 self-contained 草稿當起點。

> Since @kuhar asked for a self-contained definition and this has been sitting for a while: arith already gives most of these flags a meaning in code (`nsz`/`nnan` in the `addf`/`subf`/`mulf` folders, `contract` in `extf(truncf)`, `ninf` in the integer range inference), and `convert-arith-to-llvm` maps all seven 1:1 to the LLVM flags, so the definitions only need to be written down in arith's own terms. The `addi` description already does this for `nsw`/`nuw` ("the result is poison"), and the dialect description defines poison propagation, so the same vocabulary works here. A starting point, if it helps:
>
> ```
> Floating-point fast math flags. Each flag lets transformations assume
> something about the operation or rewrite it; without flags the operation
> follows IEEE 754.
>
> * `nnan`: the operands and the result are assumed not to be NaN. If an
>   operand is NaN, or the result would be NaN, the result is poison.
> * `ninf`: the operands and the result are assumed not to be +/-Inf. If an
>   operand is +/-Inf, or the result would be +/-Inf, the result is poison.
> * `nsz`: the sign of a zero operand or result may be flipped
>   non-deterministically. `-0.0` is not poison.
> * `arcp`: a division may be replaced by a multiplication with the
>   reciprocal, e.g. `a / b` by `a * (1.0 / b)`.
> * `contract`: the operation may be fused with a neighbouring operation
>   into one operation with a single rounding, e.g. a `mulf` feeding an
>   `addf` into an `fma`.
> * `afn`: the operation may be replaced by an approximation. This applies
>   to the `math` ops that carry this attribute.
> * `reassoc`: the operation may be replaced by an algebraically equivalent
>   expression, e.g. reassociated with neighbouring operations, even though
>   floating-point arithmetic is not associative.
> * `fast`: all of the above.
>
> `arcp`, `contract` and `reassoc` are rewrite-based: a rewrite that
> involves several operations needs the flag on all of them, and the
> operations it creates carry the intersection of the flags of the
> operations they replace. The other flags are value-based and apply to
> the operation on its own.
>
> These match the LLVM IR fast-math flags of the same name, which is what
> `convert-arith-to-llvm` lowers them to.
> ```
>
> The text renders under the `Syntax` block of `FastMathFlagsAttr` in the generated dialect doc (checked with `mlir-tblgen -gen-dialect-doc`), so the enum is the right place for it.

**風險**：草稿是我們寫的，語意照 LangRef 4392–4495 翻譯；kuhar 若對「rewrite-based」段落有意見，那是 LangRef 原有的規則，可引 LangRef L4431–4447。
