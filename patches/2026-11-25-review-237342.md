The fallback branch of `mulDivisibilities` has no test. This one reaches it (the divisor would be 9 * 2^64):

```mlir
func.func @muli_divisor_overflow(%x : i64, %y : i64) -> i64 {
  %c = arith.constant 12884901888 : i64
  %a = arith.muli %x, %c overflow<nsw, nuw> : i64
  %b = arith.muli %y, %c overflow<nsw, nuw> : i64
  %0 = arith.muli %a, %b overflow<nsw, nuw> : i64
  // CHECK: divisibility = "udiv = 9223372036854775808, sdiv = 9223372036854775808"
  %1 = "test.int_divisibility"(%0) : (i64) -> i64
  return %1 : i64
}
```

`addi` and `subi` have the same problem: they take the gcd of the operand divisors, which does not survive a wrap either. On `i8`, `select(%p, 3, 255) + 3` is reported as `udiv = 3`, and for `%p = false` the value is 2. Same for `select(%p, 3, 0) - 3`, which gives 253. The fix would be the one you have here (keep only the power-of-two part unless `nuw`/`nsw` is set), so you may want to cover them in this PR or in a follow-up.
